# ภาพเริ่มช้ากว่าตัวไฟล์: ผลตัดคนจะเหลื่อมไหม (28 พ.ย. 2026)

**สถานะ: โค้ชสั่ง "ทดไว้ก่อน ยังไม่แก้"** ไม่มีโค้ดของเว็บเปลี่ยน

## รู้อะไรแล้ว

| เรื่อง | ผล | หลักฐาน |
|---|---|---|
| FFmpeg 7.1 (ในเครื่อง) ไฟล์ภาพช้า 0.4 วิ | ผลตัดคนเหลื่อม 12 เฟรมในตัวอย่างหลังตัด (ทั้งแบบก่อนและหลัง 28 พ.ย.) และในคลิปจริงช่วงที่ลอง | ลองแล้ว (`sim.py`) |
| ตัวเล่นบนเว็บ (`src/lib/player/mp4.ts`) | ข้าม empty edit จึงให้ภาพแรกของไฟล์แบบนี้ที่ 0.000 แทน 0.4 · ผลต่อภาพกับเสียง | ลองอ่านไฟล์แล้ว · ผลต่อเสียงเป็นการอนุมาน |
| FFmpeg 5.1 (เซิร์ฟเวอร์ Modal) | ตอนเข้ารหัสวิดีโอที่ภาพช้าเป็น MP4 เติมภาพแรกซ้ำให้เริ่มที่ 0 (162 ภาพจาก 150) | เห็นตอนมันสร้างไฟล์ทดสอบเอง |
| ไฟล์จริง | ภาพเริ่มช้า 0 จาก 10 คลิปบน staging และ 0 จาก 4 ตัวอย่างในเครื่อง (เสียงเริ่มช้า 8 จาก 10) | อ่านหัวไฟล์ |
| ถ้าเหลื่อม 0.4 วิ จะเห็นแค่ไหน (คลิปตัดคนจริง 1 คลิป, 98 วิที่มีคนทั้งสองเวลา) | พื้นที่ผิดต่อพื้นที่ตัวคน: ครึ่งหนึ่งของเฟรมไม่เกิน 0.6%, 9 ใน 10 ไม่เกิน 1.4%, เกิน 2% = 4%, เกิน 5% = 1% · ตอนขยับเห็นฉากหลังโผล่ข้างผม ตอนนิ่งเป็นขอบบาง | วัดแล้ว + ดูรูป |

## ยังไม่รู้

- ป้อนไฟล์ที่ภาพช้า**จริง** (สร้างจากในเครื่อง มี empty edit) ให้ FFmpeg 5.1 บนเซิร์ฟเวอร์ รอบที่รันไป ไฟล์ทดสอบถูกเติมภาพตั้งแต่ตอนสร้าง จึงพิสูจน์ไม่ได้
- ตัวตัดแบบ `Best` และท่อนแรกของคลิปจริงบนเซิร์ฟเวอร์
- ไฟล์ของผู้ใช้บนเว็บจริง (ไม่ได้เปิดดู)

## ทำต่ออย่างไร

1. `python docs/trials/late-video/sim.py` สร้างไฟล์ทดสอบในโฟลเดอร์ข้างสคริปต์ (ใช้ `imageio_ffmpeg` ที่มีในเครื่อง) **อย่า commit ไฟล์ที่มันสร้าง**
2. แก้ `on_server.py` ให้ส่ง `late/src.mp4` กับ `normal/src.mp4` เข้าเครื่อง และให้ `sim.py` ใช้ไฟล์นั้นแทนการสร้างใหม่ แล้วรัน `python -m modal run docs/trials/late-video/on_server.py` หนึ่งรอบ (รอบวันนี้รวมประมาณ US$0.0008)
3. ถ้าจะกันไว้: บังคับให้ภาพเริ่มที่วินาที 0 ทุกขั้นบนเซิร์ฟเวอร์ (ไฟล์ตัวอย่าง, ตัวตัดคน, `render`) แตะโค้ดคู่ ต้องรีวิวและลองบน staging
